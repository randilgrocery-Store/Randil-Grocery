5. DESIGN AUDIT — WHAT BREAKS THE APPROVED DESIGN RULES
--------------------------------------------------------------------------------

[1] HERO BANNER — VIOLATION
    _buildHeader (301-342) is a full-width green gradient banner with a coloured
    glow shadow, exactly the "giant hero banner" the brief says to remove.
    Replace with a slim greeting/section row.

[2] RANDOM GRADIENTS — VIOLATION (7 of them)
    Header            0xFF00843D -> 0x006830 + 25% green glow
    Shop banner       0xFF11998E -> 0xFF38EF7D   teal->lime
    Users banner      0xFF4568DC -> 0xFFB06AB3   blue->purple
    Backup banner     0xFF159957 -> 0xFF155799   green->blue
    Cloud banner      0xFF0F2027 -> 0xFF203A43   navy->slate
    About banner      0xFF4568DC -> 0xFF5B86E5   two blues
    TabBar indicator  plain tinted box (this one is fine)
    The brief: "Semantic colors only for meaning... No random gradients."
    Every one of these is decorative, not semantic. All six should go.

[3] ONE CARD STYLE — VIOLATION (radius drift)
    borderRadius values in this file: 16, 14, 12, 10, 8, pill(999).
    Containers using plain Container + Border.all:
        1125 (user list header), 1325 (dialog hint), 1447 (dialog hint),
        1622 (Wrap), 1950 (_buildKpiChip), 1999 (_buildSettingToggleTile)
    These bypass Card/GroceryCard entirely, so even the legacy card style is
    not consistently applied here.

[4] DARK MODE — BROKEN (this is the biggest practical defect)
    Hard-coded `Colors.white` backgrounds, 10 occurrences:
        348  _buildTabBar container
        1129 user list header
        1168 user row background
        1953 _buildKpiChip
        + GrocryCard `color: Colors.white` at 1166
    Hard-coded PosAppTheme static colours bypass Theme entirely:
        bg, textDark, textGray, borderGray, primaryGreen, dangerRed,
        warningOrange, successGreen, accentBlue, lightGreen, darkGreen
    Result: on dark mode this screen renders WHITE panels on a #121212 canvas,
    with white-on-white text in places. Also `_buildSettingToggleTile` uses
    `color: PosAppTheme.bgColor` (#F4F7F6, light) as its container.
    The screen has never been tested in dark mode.

[5] NO TYPE SCALE
    Font sizes present: 24, 18, 17, 16, 14, 13, 12, 11, 10.
    No weight/size relationship. Every title is hand-styled with an inline
    TextStyle instead of a scale.

[6] PRIVATE ONE-OFF WIDGETS THAT SHOULD BE THE COMPONENT LIBRARY
    _buildKpiChip        (1944-1990)  -> should be KpiCard / StatusBadge
    _buildSettingToggleTile (1992-2013) -> needs a shared SwitchTile component
    _buildSectionBanner  (1888-1942)  -> should be a plain SectionHeader
    _AboutRow            (2017-2055)  -> fine, but hand-styled
    _buildHeader         (301-342)    -> remove per brief
    These duplicate the component library instead of using it.

[7] NO HOVER / FOCUS AFFORDANCE
    The whole screen is static Boxes. Nothing responds to the mouse. On a
    desktop POS where most interaction is a mouse click this is a real gap.

6. THE FOUR-STATE RULE — WHERE SETTINGS FAILS IT
--------------------------------------------------------------------------------

  WIDGET              LOADING            EMPTY         ERROR       DATA
  -------------------- ------------------ ------------- ----------- ----------
  Users list           CircularProgressIndicator  MISSING   MISSING     yes
  Printer list         none (sync call)   partial text  partial     yes
  Network status       none               N/A           yes (red)   yes
  Cloud status         none               "Cloud off"   yes (red)   yes
  Backup target path   none               default path  none        yes

  >>> Users tab (1074-1077):
        if (!snapshot.hasData) return Center(child: CircularProgressIndicator());
      - NO empty state: a brand-new shop with zero users shows a bare spinner
        forever (FutureBuilder only resolves hasData when the future completes,
        and even then an EMPTY LIST produces `users.length == 0` -> a header
        chip reading "0" and a completely blank list area).
      - NO error state: if getAllUsers() throws, snapshot.hasData stays false
        -> the spinner never stops and there is no message and no retry.
      - NO retry affordance.

  >>> This screen is the clearest 4-state violation in the whole app and should
      be the first consumer of AppAsync / SkeletonList / AppEmptyState /
      AppErrorState from the component library built in Step 2.

7. ROLE & PERMISSION BEHAVIOUR
--------------------------------------------------------------------------------

  * Settings is admin nav INDEX 12 of 13. Cashier nav is only 5 entries
    (Dashboard, POS, GRN, Refunds, Profile) — cashiers CANNOT reach Settings
    at all. Verified in home_screen.dart lines 50-96.

  * Inside the screen, user management is additionally gated by
    authProvider.isAdmin:
        - "Add User" button hidden          (1146)
        - per-user PopupMenu hidden         (1240)
    The user LIST itself is not gated, but the tab is unreachable to a cashier.

  * Role assignment: only UserRole.cashier is ever created. The Edit dialog
    states roles cannot be changed. There is no UI to promote a user to admin;
    that must be done out-of-band (DB or seed).

  * No wording anywhere in Settings uses "credit", "unpaid customer" or
    "debt". Only external money owed in the app is We Owe Suppliers, which is
    NOT on this screen. This rule is already satisfied here — do not break it.

8. BUGS / SMELLS FOUND (line numbers)
--------------------------------------------------------------------------------

  B1. Users tab swallows errors and can hang on the spinner.
      Line 1074-1076. See section 6.

  B2. "Reset" on the Shop tab (1031) calls _initializeControllers() only.
      It re-reads settings into the text fields. It does NOT undo anything
      already saved, and it does not clear the notice, so a user who edits ->
      saves -> clicks Reset sees the saved values "restored" and may believe
      Reset reverted them. Misleading label; it should be "Discard changes".

  B3. Cloud sync switch (811-813) writes to LOCAL STATE only.
      `_enableCloudSync` is not persisted until "Save & Sync Now" is pressed.
      There is no "Save" that persists without also triggering a network push.
      A user can toggle it, close the tab, and nothing changed — with no
      indication of the pending state.

  B4. Reset does not touch the cloud tab fields (URL / anon key) or the
      network fields partially: _initializeControllers DOES rebuild the network
      controllers from settings, but the cloud controllers are rebuilt from
      SupabaseSyncService.instance, so behavior is inconsistent between tabs.

  B5. Admin detection via string matching.
      Line 1081: `u.role.toString().toLowerCase().contains('admin')`.
      Fragile against enum renaming. Compare against the enum value instead.

  B6. Admin rows tinted with warningOrange (1167, 1173, 1211).
      Semantically wrong: an admin is not a warning. Uses a semantic colour
      for decoration — violates the "semantic colours only for meaning" rule.

  B7. Duplicate-ish user cards are not keyboard navigable and have no
      hover state; the overflow menu is the only affordance.

  B8. `_loadPrinters` (96-106) silently swallows every exception with
      `catch (_)`. A printer enumeration failure is indistinguishable from
      "no printers installed".

  B9. Restore confirm (194-213) uses a plain AlertDialog where Cancel and
      Continue are BOTH TextButtons. The destructive path ("replace all
      current data") has no visual weight and no icon. Should use
      AppConfirmDialog(destructive: true).

  B10. About tab hardcodes Version '1.0.0' while pubspec.yaml is
      version: 1.0.0+1. It will silently drift on every bump.

  B11. `withOpacity` used 18 times (deprecated in Flutter 3.44) — including
      lines 310, 317, 362, 503, 549, 812, 1167, 1173, 1211, 1676, 1910, 1932,
      1964. Use withValues(alpha:). Same deprecation the new component
      library already avoided.

  B12. Developers' setup instructions for Supabase (871-881) are shown to the
      end user, including file paths in the repo. That is developer content in
      a production screen.

  B13. Five text controllers are created but never disposed if
       _initializeControllers is called again from "Reset": _initializeControllers
       reassigns them WITHOUT disposing the old instances -> LEAK.
       Lines 56-94 and 1031. This is the most concrete resource bug in the file.

  B14. Network settings (a system/infrastructure concern) live inside the
       "Shop" tab which is labelled as business profile. Users look for LAN
       setup under "Cloud" and will not find it.

9. MISSING DATA SOURCES (Settings-specific)
--------------------------------------------------------------------------------

  M1. currency / currencySymbol — persisted and consumed, NOT editable.
      The redesign needs a currency setting ONLY if the user wants it exposed.
      Until then AppMoney falls back to 'Rs', which matches the model default
      exactly, so no display bug results from leaving it unexposed.

  M2. paperWidth (receipt width, 80mm) — persisted, used by PrintService,
      NOT editable. Selecting a 58mm printer from the dropdown will not change
      the paper width.

  M3. Printer "Connected" chip (941-948) is derived from enablePrinting only.
      It says 'Connected' when printing is merely ENABLEED. The printer may be
      missing/unplugged. The label is misleading — it means "Printing on".

  M4. No place to view app version, DB path, or DB size except a hardcoded
      About row. `DatabaseService().getDatabasePath()` exists and is already
      called in this file (142), so a real value is available.

  M5. No "server running" health detail in the top-level sense — it exists only
      inside the nested network card, and only when isServerMode is true.

  M6. No audit trail / last-changed stamp, even though ShopSettings.updatedAt
      is stored. Displaying "Settings last updated <updatedAt>" is free.

11. RECOMMENDED REDESIGN DIRECTION (for later approval — NOT implemented)
--------------------------------------------------------------------------------

  A. Remove the gradient hero header. Use the slim page header that the new
     shell already provides, plus the standard title.

  B. Drop the six decorative section banners. Replace each with
     AppSectionHeader(icon, title, subtitle).

  C. Keep the 5 tabs — they are a good information architecture. Consider
     renaming to:
        Shop · Users · Backup · Cloud · About
     (labels are already good; no need to change)

  D. Move the network/LAN card out of the Shop tab into Cloud, or into a new
     6th "Network" tab. Strongly recommended: it is the single largest
     IA problem in this screen (B14).

  E. Replace every hardcoded white with AppColors.surface; replace every
     PosAppTheme.* with context.appColors so dark mode works.

  F. Replace _buildKpiChip with KpiCard or StatusBadge; replace
     _buildSettingToggleTile with a shared themed switch tile; replace
     _buildSectionBanner with AppSectionHeader.

  G. Make the Users tab the reference implementation of the four states:
        loading  -> SkeletonList(rows: 5)
        empty    -> AppEmptyState(icon: person_off, "No users yet",
                                  action: Add User if admin)
        error    -> AppErrorState(onRetry: reload future)
        data     -> AppDataTable or the existing list

  H. Reuse AppConfirmDialog(destructive: true) for delete-user and restore.

  I. Surface paperWidth and (optionally) currency/currencySymbol — they are
     already persisted, so this is UI-only.

  J. Show a real version string instead of the hardcoded '1.0.0', and a real
     DB path/size from DatabaseService().

  K. Label the printer chip "Printing on" / "Printing off", not Connected.

  L. Fix the controller leak (B13) before touching anything else.

  ----------------------------------------------------------------------------
  BUG 1  [RED]  "All Items in Stock" contradicts "5 Stock Warnings"
               ROOT CAUSE CONFIRMED - NOT A DATA ERROR
  ----------------------------------------------------------------------------
    WHERE   product_provider.dart:121-130

      int getLowStockCount()      => _products.where((p) => p.quantity >  0
                                                     && p.quantity < 10).length;
      int getOutOfStockCount()    => _products.where((p) => p.quantity <= 0).length;
      List getLowStockProducts()  => _products.where((p) => p.quantity >  0
                                                     && p.quantity < 10).toList();
      List getOutOfStockProducts()=> _products.where((p) => p.quantity <= 0).toList();

    WHY IT BREAKS
      _buildLowStockAlert() (line 1500) reads ONLY getLowStockProducts(),
      which by its own definition EXCLUDES out-of-stock items (quantity > 0).
      So the three dashboard widgets query three DIFFERENT slices:

        Widget                      Reads                     Result
        ----------------------------------------------------------------------
        KPI "Stock Warnings" (743)  low + out                 5   correct
        Inventory donut  (1389-92)  both counts, normal =      5   correct
                                   total - low - out              out of
                                                                   stock
        Low Stock Alert   (1500)   getLowStockProducts() ONLY  []  WRONG ->
                                                                     "All Items
                                                                      in Stock"

      When EVERY problem item is out of stock, the list is empty and the card
      prints the reassuring "All Items in Stock" state.

    PROPOSED FIX (presentation only, ZERO logic change, KEEP ONE SOURCE):
      Build the reorder list as
          getLowStockProducts() + getOutOfStockProducts()
      and gate the EMPTY state on that COMBINED list, never on
      getLowStockProducts() alone. ProductProvider stays the only place stock
      is classified; the dashboard stops re-deriving status.

    !! DEEPER INCONSISTENCY - FOUR DIFFERENT "LOW STOCK" RULES EXIST TODAY !!

      RULE A  product_provider.dart:121-130   dashboard      hardcoded < 10
      RULE B  inventory_screen.dart:353       inventory      qty < (reorderLevel
                                                                  ?? 10)
      RULE C  purchase_order_screen.dart:45,203  POs        reorderLevel ?? 10
      RULE D  product.dart:75-76              MODEL         needsReorder:
            needsReorder  = reorderLevel != null && qty <= reorderLevel
            isLowStock    = reorderLevel != null && qty < reorderLevel * 2
            *** RULE D IS NEVER CALLED ANYWHERE - DEAD CODE ***

      So the Dashboard says "Low" by rule A, but you reorder from a screen
      that uses rule B/C. Fixing only the empty state keeps the numeric
      disagreement.

      RECOMMENDATION: unify on rule B, because that is what the user already
      sees in Inventory and Purchase Orders:
          quantity <= 0                    -> Out of stock
          else qty < (reorderLevel ?? 10)  -> Low
          else                             -> Normal

      OPTIONS: (a) presentation-only unification with existing getters (safe,
               but rule A vs rule B still differ numerically)
              (b) add ONE read-only stockStatusOf(Product) /
                  getReorderCandidates() to ProductProvider using rule B
                  -> TOUCHES A STATE-MANAGEMENT CLASS, needs explicit OK
              (c) leave rule A, fix only the empty state

  BUG 5  [ORANGE]  PROFIT & LOSS CARD PRESENTATION PROBLEMS
  ----------------------------------------------------------------------------
    profit_loss_panel.dart (535 lines) mixes THREE different statements into
    ONE list:

      Money In             Sales revenue / Discounts given / Net sales taken /
                           Cash-Card
      Cost of goods sold   Cost of items sold / Gross profit
      Running costs        Wastage loss / Refunds paid / Shop expenses

      of the till          Still owed to suppliers /

      How each part...     6 module tiles

    CONFIRMED PROBLEMS

    (i) "Stock on Hand (cost value)" is a BALANCE-SHEET ASSET, not a P&L line.
        It sits inside a statement whose bottom line is NET PROFIT, so a
        reader naturally subtracts it. It must move out.

    (ii) "Profit" and "Net Profit" appear as separate numbers. They are EQUAL
        whenever wastage + refunds + expenses = 0, which looks like a bug.
        The duplicate is KPI card "Gross Profit" (line 713) vs the panel's
        "NET PROFIT".

    (iii) netProfit FORMULA IS INTERNALLY INCONSISTENT
          CONFIRMED at database_service.dart:1966-1970

            final totalLoss = cogs + wastageLoss + refundLoss + expenseTotal;
            final netProfit = revenue - totalLoss;

          * discounts is COLLECTED (1836) and DISPLAYED (panel 67) but is
            NEVER SUBTRACTED. revenue is sale.totalAmount, i.e. ALREADY AFTER
            the bill's discount. So the panel prints a "Discounts given" line
            implying it reduces the result while the math already removed it.
            DOUBLE-COUNTING IN THE READER'S HEAD; the number is right, the
            presentation is wrong.
          * grossProfit = revenue - cogs uses the same revenue, so the panel's
            "Net sales taken = revenue - discounts" line is decorative - it
            feeds nothing.
          * refundLoss subtracts the refund amount but the refunded goods' COGS
            is NEVER credited back. A processed refund cuts profit by the full
            SELLING price of goods that went back on the shelf. Over time this
            systematically UNDERSTATES profit.
          * splitSales is declared (1831), returned (1982), and ALWAYS 0.
            Dead key.
          * The P&L KPI uses pl.d('netProfit') only if pl.data != null, else
            falls back to rangeStats.profit (line 684) - a SILENT FALLBACK to
            a DIFFERENT formula (revenue - currentBuyingPrice x qty, ignoring
            wastage/refunds/expenses). That is a THIRD "net profit" definition
            on the same screen.

      * P&L SUMMARY CARD (admin, 1/3 width):
          Sales Profit -> Wastage Loss -> Refund Loss -> Expenses -> NET PROFIT
        Net Profit clearly highlighted. Each line with "vs previous period".
        "Stock on Hand" REMOVED from here.
      * INVENTORY PANEL (Row 3) gains:
          "Inventory Value (cost) Rs 14,770.00 - 312 items"
        sourced from the SAME pl.d('stockValue') / pl.d('stockItems') keys.
        No new query.

      * Panel labels rewritten so discounts read as "already deducted at

      * profit_loss_panel.dart STAYS AS-IS, still used as the admin-only full

  SECTION 5 : SIDE-SHELL RISK  (Rule 8 - other screens at the new width)
################################################################################

  THIS IS THE BIGGEST TECHNICAL RISK IN THE WHOLE PASS.

  GOOD NEWS
    ResponsiveSize (core/constants/responsive.dart:10-11) reads
        MediaQuery.of(context).size.width      <- the WINDOW width
    NOT the content width. A sidebar does NOT change MediaQuery, so
    isTablet / isDesktop / productGridColumns keep their CURRENT values.
    ==> NO screen changes its layout mode. Verified in the import graph.

  THE RISK
    The real available width shrinks. pos_screen.dart:1021-1028 builds its
    grid with crossAxisCount: responsive.productGridColumns (5 on desktop)
    and childAspectRatio: 0.85 - NO fixed widths, so cards just get NARROWER
    and SHORTER. Card content (image + name + price + add button) is the
    overflow candidate.

    main.dart:56-57 currently allows a 1024x700 window with no sidebar.
    With a 232px sidebar that leaves 792px of content on a 1024 screen.

  THEME TRAP
    pos_screen.dart:1038 reads Theme.of(context).appBarTheme.backgroundColor
    for its category strip. Currently UNSET, so it falls back to the M3
    default.
    ==> WILL NOT SET appBarTheme in the new ThemeData, or the POS header
        colour changes silently.

  MITIGATIONS PROPOSED
    - Collapsible sidebar (icon rail ~64px when collapsed)
    - Default collapsed below ~1500px width
    - Bump WindowOptions.minimumSize 1024x700 -> 1280x760  (needs Q5 OK)
    - Every other screen stays byte-identical, just re-parented.
